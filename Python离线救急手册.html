Python 离线救急手册

不熟悉语法时，不必记住整个库。先把正在研究的问题缩小为三行数据，确认每一步输入、输出和类型，再回到完整案例。

读代码时先找这五件事

  1. 输入在哪里？ CSV、列表、函数参数，还是模拟器生成的数据？
  2. 一行代表什么？ 一天、一条短信、一个人，还是一个时间步？
  3. 变量的类型与形状是什么？ 列表、字典、表格、数组和Tensor的操作不同。
  4. 核心函数返回什么？ 用 print() 观察一次小输入的结果。
  5. 怎么证明结果没算错？ 手算、简单基线、独立断言、留出数据分别解决不同问题。

最常见的 Python 结构

temperatures = [20, 24, 22]            # 列表：按位置存放
record = {"date": "day1", "temp": 20} # 字典：按名称查值
print(temperatures[0], record["temp"])

def above_limit(values, limit=23):    # 定义可复用函数，默认阈值23
    selected = []
    for value in values:
        if value > limit:
            selected.append(value)
    return selected                  # return 交还结果

answer = above_limit(temperatures)
assert answer == [24]                 # 不符合预期就立即报错

缩进表示结构，通常每层四个空格。冒号之后的缩进块属于 def、for 或 if。print()显示给人看，return把值交给调用者，二者不等价。

[x * 2 for x in values] 是列表推导式，可以先改写为循环理解。with open(...) as f 管理文件打开和关闭。try/except 用于处理明确的可恢复异常，不应为了让代码“看起来成功”而吞掉所有错误。

数组与表格：先看形状

import numpy as np
x = np.array([[1, 10], [3, 30], [5, 50]])
print(x.shape)       # (3, 2)：3行、2列
print(x[:, 0])       # 第0列：[1, 3, 5]
print(x.mean(axis=0))# 沿行方向汇总，得到两列均值：[3, 30]
print(x.mean(axis=1))# 每行内部汇总，得到3个均值

NumPy/Tensor通常从0开始编号；切片右端不包含在内。x[0:2]取第0、1行。.reshape(...)只改变组织方式，不会替你确认“样本”和“特征”放对了位置。

对于pandas表格，先运行 df.head()、df.dtypes、df.shape、df.isna().sum()。df["temp"]是一列，df[["temp"]]仍是二维表格。不同形状可能触发模型输入错误。

分类神经网络的类别标签通常需要整数索引；使用PyTorch交叉熵时，标签应为 torch.long。输入特征通常是浮点Tensor。把标签变成float不能解决类别索引问题。

报错时按这个顺序处理

  1. 先保存自己的修改，再重启内核并从第一格顺序运行，排除旧变量影响。
  2. 阅读 traceback 最后的异常类型和信息，再往上找到最近一处属于本课 solution.py 或单元格的调用。
  3. 在出错语句前打印变量的 type()、.shape、少量内容；不要一次打印整个数据集。
  4. 把出错函数单独拿出来，用三行数据重现，先写出你认为应该得到的结果。
  5. 对照参考答案，只比较相关部分。一次改一个因素，重新运行并记录结果。
报错 首先检查
NameError 变量名是否拼错、定义它的前一格是否运行
KeyError 字典键或CSV列名是否存在，是否带空格
IndexError 索引是否超过长度，数组维度是否与想象一致
TypeError 字符串与数字是否混用、函数参数是否传错
ValueError / shape mismatch 样本数、列数、Tensor维度和标签长度是否匹配
FileNotFoundError 当前目录、文件名、课程assets是否完整
ModuleNotFoundError / DLL load failed 是否选中了课程内核；再查根目录故障排查
AssertionError 哪个具体预期被违反；不要直接删除断言

修改模型的最小流程

先写一句假设，例如“增加过去7天的历史特征可能减少预测误差”。固定同一数据划分，先保存基线成绩，再只改一个条件；在验证集决定是否保留，最后再看测试集。测试结果差也是结果，不应改随机种子直到赢为止。

没有真实标签时，不能只用“输出看上去合理”证明模型正确。规划检查约束，仿真核对手算边界，检索核对相关文档，生成答案核对原文依据；不同问题要用不同检查方法。
